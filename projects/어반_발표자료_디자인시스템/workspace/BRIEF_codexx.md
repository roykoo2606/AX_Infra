## 1. 이 문서가 무엇이어야 하는가

**AI가 읽고 그대로 장표를 생산할 수 있는 실행 스펙**입니다. 사람이 읽는 감상형 가이드가 아닙니다.

목표 워크플로우는 이렇습니다:

```
컨텍스트·방향성 입력  →  design.md 참조  →  컴포넌트 조립(HTML)  →  렌더(PNG @2x)  →  사람이 마무리 터치
                                    ↑                    ↑
                          실사 이미지 생성 활용     아이콘 설계 규칙
```

따라서 design.md는 다음을 만족해야 합니다.

- **값이 확정적일 것** — "은은한 남색" 같은 서술 금지. `#0A082B` 처럼 쓸 수 있는 값으로.
- **복사해 쓸 수 있을 것** — 컴포넌트마다 실제 HTML/CSS 스니펫을 포함.
- **판정 가능할 것** — 산출물이 규격에 맞는지 체크리스트로 검증 가능.
- 서술은 한국어, 코드·토큰명·주석은 영어.

## 4. design.md 필수 구성

1. **목적·적용범위·사용법** — 이 문서를 받은 에이전트가 무엇부터 해야 하는지
2. **캔버스 규격** — 1600×900 기준, @2x(3200×1800) 출력. 안전 여백.
3. **디자인 토큰** — CSS custom property 형태. 색/타이포/간격/라운드/그림자/그라디언트.
   라이트·다크 두 모드를 하나의 소스에서 구동하는 방식까지 (기존 `mode구동` HTML 참고).
4. **타이포그래피 스케일** — 역할별(eyebrow/display/h1/h2/body/caption/meta) 크기·웨이트·자간·행간 표.
5. **레이아웃 그리드** — 여백·컬럼·z-index 체계.
6. **컴포넌트 카탈로그** — 각 항목에 용도 / HTML+CSS 스니펫 / 사용 조건 / 금지사항.
   최소: 표지, 섹션 구분, 상단 메타바, 카피블록, 이미지 카드(+캡션), pill 태그,
   KPI·수치 타일, 표, 프로세스·플로우, 하단 푸터 룰.
7. **아이콘 설계 규칙** — 스타일(선/면), 스트로크 굵기, 그리드, 라운드, 색 적용 방식, 생성 프롬프트 지침.
8. **실사 이미지 활용 규칙** — 언제 쓰는지, 톤·색보정 기준, 브랜드 그라디언트와의 관계,
   캡션 표기법, 생성 시 프롬프트 가이드(의료·병리 도메인 포함).
9. **스킬 연동** — 아래 5절 참조.
10. **슬라이드 유형별 템플릿** — 표지 / 목차 / 본문 / 다이어그램 / 데이터 / 마무리.
11. **안티패턴** — 하지 말아야 할 것을 실제 사례로.
12. **산출 파이프라인** — HTML → 헤드리스 Chrome → PNG @2x → PPTX 삽입. 실제 명령까지.
13. **검수 체크리스트** — 사람이 마무리 터치 전에 기계적으로 확인할 항목.

## 5. 스킬 연동 (컴포넌트 네이티브화)

이 저장소에는 이미 다음 스킬이 있습니다. design.md는 **이들이 어떤 토큰·규칙을 따라야 하는지**를
지정하는 상위 규격이어야 합니다. 스킬을 다시 만들지 말고, 연결 지점만 정의하십시오.

| 스킬 | 역할 | design.md가 규정할 것 |
|---|---|---|
| `infographic-builder` | 자립형 HTML 인포그래픽 → 헤드리스 Chrome PNG @2x 렌더 | 이 스킬이 써야 할 토큰·컴포넌트·톤 |
| `archify` | 아키텍처·플로우·시퀀스 다이어그램 (HTML+SVG, 테마 토글) | 다이어그램 색·선 두께·노드 스타일 |
| `dataviz` | 차트·대시보드 색 체계 | 시리즈 색 순서, 축·범례 규칙 |

각 스킬 호출 시 넘길 "브랜드 컨텍스트 블록"을 design.md 안에 **복붙 가능한 형태로** 제공하십시오.
